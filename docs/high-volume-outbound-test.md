# Test B: High-Volume Outbound Transfer Detection

## 1. Objective

The objective of Test B was to verify that the network security lab could identify unusually large outbound TCP transfers using Suricata flow records and a custom Python detection script.

The test was designed to demonstrate how high-volume network activity can be identified for security review. It was a controlled laboratory simulation, not an actual internet data-exfiltration incident.

## 2. Test Environment

| Component | Configuration |
|---|---|
| Monitoring system | Ubuntu 24.04.5 LTS |
| Network IDS | Suricata 7.0.3 |
| Traffic generator | Ubuntu netcat |
| Receiving machine | Kali Linux |
| Ubuntu test IP | 10.106.155.63 |
| Kali receiving IP | 10.106.155.192 |
| Receiving port | TCP 5201 |
| Detection script | parser/flow_volume_detector.py |
| Detection threshold | 102,400 bytes (100 KiB) |

## 3. Test Procedure

A netcat listener was started on Kali Linux to receive the test data:

```bash
nc -lvk 5201 > received_outbound_test.bin
## 4. Suricata Evidence

Suricata recorded the TCP flow generated by the transfer.

The relevant flow information included:

- Source IP: 10.106.155.63
- Destination IP: 10.106.155.192
- Destination port: 5201
- Protocol: TCP
- Bytes to server: 274,560
- Bytes to client: 4,166

The recorded traffic exceeded the configured 100 KiB detection threshold.

## 5. Detection Logic

The custom script `parser/flow_volume_detector.py` inspected Suricata EVE JSON flow records. It identifies TCP flows, validates IP addresses, checks traffic direction against the configured test-policy network boundary, and flags transfers exceeding 102,400 bytes.

The detected flow was classified as:

`HIGH_VOLUME_OUTBOUND_TRANSFER`

## 6. Duplicate Flow Handling

The same flow ID appeared more than once in the EVE log. The detector was updated to track previously processed flow IDs so duplicate records would not inflate the results.

## 8. Test Result

**Result: SUCCESSFUL**

The detector identified the controlled transfer because its recorded byte count exceeded the configured threshold.

## 9. Security Limitations

This experiment took place within a controlled virtual-machine environment. The destination IP, 10.106.155.192, belonged to the Kali Linux test machine, not an external attacker or internet destination.

The term outbound refers to the direction defined by the detector's configured test-policy network boundary. This test demonstrates high-volume transfer detection, not confirmed internet exfiltration.

The detector did not block traffic or modify a Network ACL. Automatic containment remained disabled.

The NACL remediation component was tested separately at the LocalStack API level. LocalStack API success does not demonstrate actual packet filtering or production AWS data-plane enforcement.

## 10. Conclusion

Test B demonstrated that Suricata flow records can provide traffic-volume information and that a custom Python detector can identify transfers exceeding a defined byte threshold.

Further production validation would require real AWS networking, deployed event-driven integration, and verified packet-level containment.
